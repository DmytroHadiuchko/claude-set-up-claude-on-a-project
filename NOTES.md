# Notes

## 1. CLAUDE.md

У `CLAUDE.md` я додав контекст проєкту для Claude Code:

- **Опис проєкту** — невеликий Express REST API (users + health check), стартовий проєкт курсу.
- **Архітектура** — `server.js` збирає застосунок і експортує `app` (`listen()` лише при прямому запуску); `routes/<resource>.js` — по роутеру на ресурс, тільки валідація й статус-коди; `db/store.js` — in-memory сховище, через яке йдуть усі читання/записи; `tests/*.test.js` — `node:test` + `supertest` проти експортованого `app`.
- **Як запустити** — `npm run dev` (API на `http://localhost:3000`, порт з `PORT`), `npm test` — тести, `npm run lint` — ESLint. CI запускає lint і тести на кожен push/PR.
- **Конвенції** — CommonJS, формат помилок `{ "error": "..." }`, `Number(...)` для `:id`, порядок додавання нового ресурсу.
- **Secrets** — заборона комітити будь-які креди (API-ключі, secret keys, токени, паролі, приватні ключі); секрети лише в `.env` / змінних середовища; staging тільки явними шляхами з переглядом `git diff --staged`; хук не обходити, а прибирати секрет.

## 2. Permissions (`.claude/settings.json`)

- **allow** — `Bash(npm test:*)`, `Bash(node --test:*)`: Claude може запускати тести самостійно, без запиту дозволу.
- **deny** — `Read(./.env)`: Claude заборонено читати `.env` з міркувань безпеки, бо там можуть бути секрети.
- **deny** — `git add .env*`, `git add -A`, `git add --all`, `git add .`: Claude не може масово додати файли в коміт чи застейджити `.env` — тільки явні шляхи.
- **ask** — `Bash(git push:*)`: Claude може пушити гілку, але тільки після моєї явної згоди на кожен push.
- **hook** — `PreToolUse` → `.claude/hooks/check-secrets.sh`: перед кожним `git commit` перевіряє staged зміни і блокує коміт, якщо там є `.env*` (крім `.env.example`) або щось схоже на секрет (AWS, OpenAI/Anthropic, GitHub, Slack ключі, приватні ключі, `apiKey = "..."`).
  - Чому хук, а не тільки permissions: permissions бачать лише текст команди, а не вміст файлів — ловити секрети в коді може тільки хук.
  - Обмеження: не бачить файли, які стейджить сам `git commit -a` або `git add x && git commit` в одній команді; ключ без характерного префікса в змінній з «невинною» назвою не впіймає.
  - `.gitignore` свідомо не змінювали (там `.env` з пробілами на початку рядка, тож фактично не ігнорується) — тому хук окремо перевіряє staged `.env*`.
